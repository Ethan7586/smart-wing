## 5. 部署过程中踩过的坑（不要重复踩）

1. **不要把代码放 `/var/www` 下。** 阿里云云安全中心（aegis agent）会监控这类经典 web 根目录，
   往里面快速写入大量文件会被判定为"投放"行为并清空目录——**实测两次**，第一次在 `/var/www`
   踩到，改到 `/opt` 后第二次同样的操作模式**依然被清空**，说明触发条件是"同一 SSH 会话短时间内
   高频文件写入"这个行为模式本身，跟目录路径无关。**唯一验证稳定的传输方式是 `git clone`**（git
   内部文件写入不会触发这个检测），不要用 `scp`、`cat > file` 批量写、或者传大压缩包。
2. **SFTP 子系统在这台服务器上不可用**（`scp`/`sftp` 会报 `No such file` 之类的错误），别指望这条路。
3. **`apt upgrade` 会把 aegis.service 杀死**（信号 KILL），服务标记为 failed 但有僵尸进程残留，
   不影响部署但如果用户在意可以之后 `systemctl restart aegis` 试试拉回来。
4. **本机（Windows）访问 GitHub 需要显式给 git 配代理**，v2rayN 开着不代表 git 会用它：
   ```
   git config --global http.proxy socks5://127.0.0.1:10808
   git config --global https.proxy socks5://127.0.0.1:10808
   ```
   （端口以用户实际 v2rayN 面板显示的 `Local:[mixed:xxxx]` 为准，当时是 10808）
5. **数据库密码含特殊字符要 URL 编码**才能用在连接串里，见第 3 节。
6. **`npm install` 第一次因为 SSH channel 空闲超时被打断**（不是命令本身失败，是控制连接的
   工具超时机制）；重跑用 `nohup ... > logfile 2>&1 &` 让它脱离 SSH 会话生命周期，避免同样问题。

## 6. 尚未解决、需要用户自己决定的开放问题

1. **数据合规**：Supabase 新加坡区域是否满足备案/合规要求（覆盖到数据存放地，而不只是域名和
   服务器）？如果不满足，需要把 Supabase 换成阿里云 RDS 自建 Postgres，这是比换区域大得多的工程，
   RLS 和 REST-RPC 那套机制需要自己搭一层（比如自部署 PostgREST）。
2. **1000 人并发**：用户明确表示"先能访问，并发的事以后再说"。当前 `ecosystem.config.cjs` 是
   `instances: 1, exec_mode: 'fork'`（单进程，只用 1 个核），后续要支撑高并发时需要改成
   `exec_mode: 'cluster'` + 多实例，另外要检查实际带宽（不要用文档里"3Mbps 起步"这个最低值）和
   Supabase Free Plan 的连接数/请求频率限制。
3. **`aegis.service` 是否需要修复**：目前处于 failed 状态，不影响部署，但作为购买过的安全服务，
   用户可能想让它重新工作。

```bash
cd /opt/zhudatuan

# 2. 构建
npm run build
ls -la dist/server/index.js   # 验证产物存在

# 3. 启动
pm2 start deploy/ecosystem.config.cjs
pm2 startup
pm2 save
pm2 status

# 4. 部署 Caddy 配置（域名已改成 hbbtzn.com，不是 zhudatuan.com）
cp deploy/Caddyfile /etc/caddy/Caddyfile
systemctl reload caddy

# 5. 防火墙（注意顺序，先放行再 enable，否则会把自己锁在 SSH 外面）
ufw allow 80/tcp
ufw allow 443/tcp
ufw allow 22/tcp
ufw enable
# 同时确认阿里云控制台 ECS 安全组也放行了 80/443/22

# 6. 验证
curl -I http://localhost:3000
curl https://hbbtzn.com/api/health
# 浏览器打开 https://hbbtzn.com，走一遍登录（用 DEMO_LOGIN_CODE）→ 浏览商品 → 加购物车 → 下单
```
