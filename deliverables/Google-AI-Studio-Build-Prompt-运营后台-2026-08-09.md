## 一、应用身份与定位

App 名称：智慧翼企业福利商城 · 运营后台（Smart Wing Admin Console）

一句话定位：这不是一个带侧边栏的通用后台管理模板，而是一个让运营人员在 30 秒内看清问题、3 分钟内做出正确动作、且每次动作都可追溯的**企业福利电商经营操作系统**。使用者是商城运营、供应商对接、财务对账人员，服务对象是企业客户（如国企/央企）为员工发放的福利商城。

技术栈要求：
- React + TypeScript + Tailwind CSS（AI Studio 默认技术栈即可）
- 集成 Gemini API（`@google/genai`），用于下方"AI 运营协作者"相关功能
- 桌面端优先，最小宽度 1080px，不需要做移动端适配
- 全部使用 Mock 数据（本地 JSON / 内存状态），不连接真实后端；但数据结构要贴近生产字段，方便后续接真实 API

视觉风格（严格遵循，不要用默认的浅灰后台模板）：
- 深藏青（#10294d → #07182f 渐变）侧边栏 + 白色主内容区
- 主色：蓝 #1769ff，强调色：青 #32c7ff；状态色：警告 #f59e0b、危险 #ef476f、成功 #15a46b
- 卡片圆角 14px，浅阴影，信息密度偏高（企业级 SaaS 风格，不是电商 C 端风格），字号偏小（13-14px 正文）
- 中文界面（zh-CN），字体 Inter / 系统默认中文字体

左侧导航固定六个工作台入口（数字角标显示待处理数量）：

1. **经营驾驶舱**（首页）
2. **商品治理台**
3. **订单履约台**
4. **企业福利台**
5. **供应商协同台**

## 三、各模块详细需求

### 3.1 经营驾驶舱（首页）

首页只展示"决定"，不展示"数据堆砌"。分四个区块：

1. **必须立即处理**：卡片列表，每张卡包含——影响金额/人数、发生时间、责任人、SLA 倒计时、根因摘要、一个主操作按钮（如"去处理"）、详情入口。数据示例：库存冲突订单、临近 SLA 未处理的商品审核、预算超支预警。
2. **今天的经营结果**：4 个统计卡——GMV、预算消耗率、员工活跃度、履约健康度，每个卡带环比数据和迷你趋势线。
3. **需要确认的建议（AI 生成）**：列表，每条建议标注置信度百分比、生成依据（如"基于近7天订单异常模式"）、"采纳"/"忽略"两个按钮，点击"采纳"需二次确认弹窗。
4. **系统健康**：一行状态灯——供应商接口、库存同步、支付回调、数据任务、告警队列，绿/黄/红三态。

### 3.2 商品治理台

顶部展示商品状态机进度条：`草稿 → 已导入 → 待补全 → 待分类审核 → 待发布审核 → 已发布 → 已下架/归档`。

- **商品队列**：表格视图，可按供应商、企业、类目、风险等级、缺失字段、审核人、状态筛选；支持多选批量操作（批量审核通过、批量打回、批量下架）。
- **商品详情抽屉**：点击一行展开右侧抽屉，包含 SPU/SKU、价格、库存、图文、供应商、适用企业范围、历史版本 diff（用红/绿高亮字段变更）。
- **AI 分类建议区**：对每个"待分类审核"商品，展示 AI 给出的三级类目建议 + 置信度条；置信度 < 某阈值（如 70%）的商品自动打上"需人工复核"标签排在队列最前。
- **发布中心**：发布前必须通过校验清单（类目✓ 价格✓ 库存✓ 协议✓ 图片✓ 企业可见范围✓），任一项未过不允许点击"发布"；支持"定时发布"和"一键回滚到上一版本"。
- **审计标签页**：时间线形式展示"谁在何时以什么理由改变了价格/库存/类目/可售范围/状态"。

首页"10 个商品待分类审核"的问题必须在此处显示为具体可处理的队列项，而不是空白页。

### 3.3 订单履约台

默认视图不是"全部订单列表"，而是**问题订单视图**：异常订单、临近 SLA、等待人工处理、退款风险，用 Tab 切换"待处理 / 全部 / 已归档"。

- **单订单详情页**：一条时间线，从上到下依次是——创建、库存预占、支付、供应商接单、发货、签收、售后、退款，每个节点带时间戳和状态图标；同一页面还要有客户权益卡片、商品快照、资金分摊表、供应商事件日志、操作审计记录。
- **护栏交互**：退款、补偿、改价、强制关单这几个按钮点击后必须弹出确认弹窗，弹窗内要求填写"操作原因"文本框，并展示"影响范围"（如涉及金额、涉及用户），确认后才真正执行（Mock 环境下即状态流转）。
- 外部调用（如通知供应商）展示"重试记录"和"人工接管"按钮，模拟幂等与容错。

### 3.4 企业福利台（Smart Wing 与普通商城的核心差异，需重点实现）

核心对象链条：`企业 → 福利计划 → 部门/人群 → 预算 → 资格 → 可见商品 → 使用结果`。

页面需求：
- 企业列表 → 点进单个企业详情，展示该企业的福利计划列表（预算包、发放周期、余额来源、可购类目范围）。
- 员工资格与组织同步状态（模拟从企业 HR 系统同步部门/人员）。
- 预算消耗仪表盘：按部门/人群拆分的预算使用率进度条，超过阈值（如 80%/100%）变黄/变红并生成预警 case。
- 企业专属价格展示（同一商品对不同企业的差异化价格）。
- 归属报表：可导出（Mock 导出按钮即可）预算使用明细。

### 3.5 供应商协同台

- 供应商列表 + 评分卡（商品导入质量、库存延迟率、履约 SLA 达成率）。
- 结算单列表，状态：待确认、已确认、已支付、有争议。
- 异常重试记录（如库存同步失败自动重试 N 次的日志）。

### 3.6 财务与对账台

- 三方勾稽视图：订单流水 / 支付流水 / 账户流水 三栏并排，差异行高亮标红。
- 每条差异可一键"生成 case"进入待处理队列，不能被忽略。

### 3.7 系统治理台

- 组织架构树、角色与权限范围矩阵（角色 × 数据范围 的可视化表格）。
- 集成凭据列表（脱敏展示，如 `sk-****1234`，只显示后 4 位）。
- 接口健康监控列表、审计日志全量检索、数据保留策略配置、告警规则配置。

## 四、全局交互标准（务必实现，这是本原型和普通后台模板的区别）

1. **对象优先**：商品、订单、企业、员工、预算、供应商、结算单、告警这几类对象，无论从哪个入口点进去都应该能看到"上下游关联"（例如从一个订单能跳到对应商品、对应企业福利计划）。
2. **Case（问题单）优先于通知**：所有异常不是简单的小红点，而是可追踪的工单，状态机为 `发现 → 分级 → 指派 → 处理 → 验证 → 关闭 → 复盘`。做一个全局的"Case 中心"侧边抽屉或页面，汇总所有工作台产生的 case。
3. **不可逆操作必须可解释**：退款、预算调整、商品发布、权限提升、供应商结算，这些按钮点击后的确认弹窗必须展示"操作人、理由、前后值、关联证据"四要素。
4. **全局搜索/命令栏**：顶部搜索框支持搜索订单号、商品、员工、企业、供应商、退款号；并演示一条"自然语言命令"能力，例如输入"查看华北大区本月预算异常"能跳转到对应的过滤结果页（可以是规则匹配的 Mock 实现，不需要真正接大模型做 NL2SQL）。

## 五、AI 运营协作者（用 Gemini API 实现，务必做出"受控"而非"自由聊天"的观感）

设计原则：AI 不拥有最终业务权力，只负责发现、总结、建议、填充、解释、编排；发布、退款、扣款、授权、删除等动作必须人工确认。界面上要让这个"受控"感明确可见（比如 AI 建议卡片统一用紫色/靛蓝色边框区分于普通数据卡片，并且写死"AI 建议 · 需人工确认"标签）。

优先实现以下 2-3 个 AI 能力（不要一次塞 5 个都做浅，选 2-3 个做完整闭环）：

1. **商品分类 Copilot**：在商品治理台，调用 Gemini API，输入商品标题/属性/供应商类目，输出建议的三级类目 + 置信度 + 简短理由。人工点击"采纳"或"修改后采纳"，采纳记录要能在审计里查到。
2. **运营异常 Copilot**：在驾驶舱，调用 Gemini API 把当前 Mock 的订单/库存/预算异常数据汇总，生成"发生了什么、影响谁、可能原因、建议动作"的结构化摘要卡片，而不是一段自由文本。
3.（可选）**数据问答 Copilot**：全局搜索栏里支持自然语言提问，Gemini 把问题转成对 Mock 数据的过滤/聚合操作并返回图表或列表，明确展示"仅查询你有权限范围内的数据"。

工具权限分级（在系统治理台里做一个"AI 权限分级"说明页，把下面这张表做成静态展示即可，帮助评审者理解设计意图）：

| 等级 | 说明 | 是否可自动执行 |
|---|---|---|
| L0 解释 | 总结订单、解释指标、回答 SOP | 可以 |
| L1 建议 | 推荐类目、预测预算、识别异常 | 可以生成，需展示证据和置信度 |
| L2 编排 | 创建审核 case、分派负责人 | 可自动创建草稿，指派需确认 |
| L3 业务写入 | 发布商品、调整价格、退款 | 必须人工确认，关键操作双人复核 |
| L4 外部行动 | 给供应商下单、支付、对外通知 | 默认禁止自动执行 |

AI 绝不能做的事（做成一条固定的免责/边界说明，展示克制感）：读取或输出密钥/密码等敏感凭据；绕过角色和数据范围权限；自动退款/自动改价/自动发布/自动扣预算；在没有证据时编造库存、政策或经营数字。

## 七、验收标准（生成后请自检）

1. 运营人员理论上不需要打开数据库、不需要问研发，就能通过界面把"10 个待分类商品"处理到"已发布"状态。
2. 任意一个退款/改价/发布类按钮点击后都有二次确认 + 理由输入，不能一键裸执行。
3. 驾驶舱首页任意一张"必须立即处理"卡片点击后，能准确跳转到对应工作台的对应记录，而不是跳到空白页或首页。
4. 至少一个 AI Copilot 功能是真实调用 Gemini API 生成内容的，不是纯静态假文案。
5. 整体视觉统一为深藏青侧边栏 + 蓝/青强调色的企业级风格，不能是默认的浅灰 Admin 模板配色。
