# Smart Wing 运营后台 · 登录页 Build Prompt

> 用途：粘贴进 Google AI Studio 的 Build 输入框，生成 `smart.hbbtzn.com` 管理后台的登录页。
> 配套：`Google-AI-Studio-Build-Prompt-运营后台-2026-08-09.md`（登录成功后进入的驾驶舱）。
> 设计前提：这一页不是"一个居中的账号密码框"，而是运营人员每天接触系统的**第一道信任界面**。
> 它要同时回答三件事：这是什么系统、系统现在健不健康、我这次登录会拿到什么权限、这次登录会被谁看见。

## 前置技术约束（生成前先确认，否则登录页做得再好也跑不通）

真实认证 API 在 **`https://hbbtzn.com`**，管理后台在 **`https://smart.hbbtzn.com`**，属于跨源调用。
当前 Worker 的响应不带任何 CORS 头，浏览器会拦截。三选一后再接真实接口：

1. 把管理后台挂到 `hbbtzn.com/admin`（同源，改动最小，推荐）
2. 给 Worker 加 `Access-Control-Allow-Origin: https://smart.hbbtzn.com` + `Allow-Credentials: true` + OPTIONS 预检
3. 在 `smart.hbbtzn.com` 前置反代，把 `/api/*` 转发到 `hbbtzn.com`

**本提示词生成的原型先用 Mock 实现全部状态机**，并把接口地址抽成 `const API_BASE`，联调时改一行即可。

## 六、状态机（本页的核心价值，请逐条实现，不要合并成一个"登录失败"）

### 6.1 环境状态条

启动时请求 `GET {API_BASE}/api/health`，返回：

```json
{ "status": "ok|degraded", "checks": { "database": "...", "authentication": "...", "piiEncryption": "..." },
  "database": { "provider": "Supabase PostgreSQL", "region": "..." } }
```

渲染规则：

| status | 表现 |
|---|---|
| `ok` | 一行绿点细条："系统就绪 · 数据库 {region} · 会话服务正常"，高度 32px，不抢视线 |
| `degraded` | 琥珀色条，**必须点名是哪一项未就绪**（逐个检查 checks 三项），文案如"隐私加密未配置，登录后将无法创建订单"。登录按钮**仍然可用**，因为 degraded 不等于不能登录 |
| 请求失败 | 灰色条："无法获取系统状态，可继续尝试登录"，并提供"重试"文字按钮 |

### 6.2 登录提交的全部分支

| 场景 | HTTP / code | 界面表现 |
|---|---|---|
| 成功 | 200 | 按钮转成功态 600ms，卡片下方展开**权限徽章区**（见 6.3），再跳转驾驶舱 |
| 访问码错误 | 401 `INVALID_ACCESS_CODE` | 输入框转危险描边 + 左右轻微抖动一次（≤160ms），下方红字"访问码不正确"，并显示"本窗口内已失败 N 次，连续 5 次将封禁 15 分钟"的计数 |
| 触发限流 | 429 `LOGIN_RATE_LIMITED` | 整个表单禁用，显示**真实倒计时**（mm:ss，每秒刷新），文案"来源已被临时封禁，剩余 14:32"，倒计时归零自动恢复可用 |
| 演示账号未初始化 | 503 `DEMO_ACTOR_NOT_READY` | 琥珀提示"演示员工尚未初始化，请联系雍彻科技完成环境准备"，并给出 `requestId` 供排查（可一键复制） |
| 输入不合法 | 前端拦截 | 少于 8 位时按钮保持禁用，输入框下方灰字提示位数要求，**不要等提交后才报错** |
| 网络/超时 | fetch 抛错 | "无法连接服务端，请检查网络后重试"，并保留已输入内容，提供"重试"按钮 |
| 已存在有效会话 | 启动时 `GET /api/v1/auth/session` 返回 200 | 不显示登录表单，直接显示"检测到有效会话，正在进入…"并跳转 |

**所有错误提示必须携带可复制的 `requestId`**（小号等宽字体，点击复制并 toast 反馈）。这是运营向技术报障时唯一有用的信息。

### 6.3 登录成功后的权限徽章区（这是本页与普通登录页的分水岭）

成功后不要立刻粗暴跳转。先在卡片内用 400ms 展开一块权限摘要，停留约 1.2 秒再进入驾驶舱：

- 第一行：`employeeNo` + 角色徽章（如 `mall_admin` 显示为"商城管理员"，用主色描边胶囊）
- 第二行：**本次会话获得的权限**，把 `permissions` 数组渲染成小徽章，并翻译成中文动作名
  （`order:create` → 创建订单、`finance:refund` → 执行退款、`finance:reconcile` → 查看对账）
- 第三行灰字：会话到期时间（当前时间 + 8 小时，显示为具体时刻，不要写"8小时后"）
- **不要显示 `userId`、Cookie 值、token 或任何密钥**

权限徽章要做**能力分级**：高敏感权限（含 `finance:` 前缀、`refund`、`role`）用琥珀色描边并加锁形小标，普通权限用中性灰。让人一眼看出"我这次登录握着什么"。

## 七、交互细节

- Enter 提交；Esc 清空输入框；提交中 Tab 焦点锁在表单内
- 提交中：按钮显示 spinner + "正在验证…"，**最小展示 400ms**，避免本地极快返回时的闪烁
- 防重复提交：提交中禁用按钮与输入框，重复回车无效
- 明文切换按钮必须有 `aria-label`，切换后 3 秒自动切回密文
- 失败后自动全选输入框内容，便于直接覆盖重输
- 整页无横向滚动；1080px 宽度下左侧品牌区可压缩至 46%，低于 900px 时品牌区隐藏、表单居中

## 八、可访问性

- 所有输入有 `<label>` 关联，不用 placeholder 代替标签
- 错误提示容器 `role="alert" aria-live="assertive"`；环境状态条 `aria-live="polite"`
- 焦点环使用主色 2px outline，不要 `outline: none`
- 正文与背景对比度 ≥ 4.5:1；灰字最浅不低于 `#5b6b82`

## 九、明确禁止

- 不要编造运营数据、在线人数、"已服务 N 家企业"之类的营销数字
- 不要把未接入的 SSO / 微信做成可点击并弹出假二维码
- 不要在前端存储访问码、不要写入 localStorage、不要打印到 console
- 不要用"登录失败，请重试"这种吞掉错误码的兜底文案
- 不要加载任何外部字体、图片或 CDN 资源

## 十、生成后自检清单

1. 断网状态下打开页面：环境状态条是否降级为灰色且给出重试，而不是白屏或无限 loading
2. 连续输错 5 次：是否出现真实倒计时且表单整体禁用，倒计时结束是否自动恢复
3. 登录成功：权限徽章是否按 `finance:` 前缀做了高敏感分级
4. 任一错误态：`requestId` 是否可见且可一键复制
5. 键盘全流程：Tab → 输入 → Enter 能否完成登录，焦点环是否始终可见
6. 900px 窄窗：品牌区是否正确隐藏、表单是否居中且无横向滚动
7. 全页是否出现任何一个"未接入却可点击"的按钮（应为 0 个）
