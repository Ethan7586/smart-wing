## 4. 编码约束

- DDD 分层：`domain`（零 IO）→ `application` → `interface`；`infrastructure` 实现 `port`。跨模块只经 port 或领域事件。
- SOLID、迪米特法则；**一个文件一个主要公共概念，超 299 行必须先按职责拆分**（`npm run check:lines` 是硬门禁，不要靠加豁免绕过）。
- 命名：目录单数小写英文；类/组件 PascalCase；函数/变量 camelCase；常量 UPPERCASE。除 cli、代码审计、配置文件、SQL 迁移和测试外，自有文件与目录名**不得出现下划线、连字符、空格或无意义缩写**。`V1` 这类版本后缀已全部清理，不要再引入。
- **金额一律整数分，禁止浮点。**
- 禁止重复逻辑与重复配置；禁止调用点断裂。
- 彻底移除演示态与兼容层，**不保留转发别名**——要么改完所有调用点并删除旧模块，要么不动。
- 数据库改动一律走新迁移文件，**不得修改已应用的迁移**。
- 所有写路径必须要求 `Idempotency-Key`，并落幂等记录；高风险操作要求服务端会话绑定的二次认证。

## 5. 验证工具与它的盲区

```
npm run quality                         # CI 跑的就是这条，25 步
node scripts/audit/index.mjs --summary  # 调用点断裂 / 重复逻辑 / 命名 / 边界
npm run check:lines
npm run check:vi                        # VI 棘轮，只许降不许升
```

**盲区**：`scripts/audit/callgraph.mjs` 只校验导出名，**不校验函数签名**。前任改了 `decide()` 的签名而漏改 2 个调用点，导致后端每次鉴权全返回 403，审计全绿也没抓到，是跑 `npm test` 才发现的。**改动任何函数签名后必须跑 `npm test`。**

`npm run check:vi` 是棘轮：存量只许降不许升。确需上升必须用单行 `// vi-allow: <规则> <理由>`，无理由的豁免本身算失败。整体重录基线需要 `--reason` 并在 commit message 里写明接受了哪些欠账。
