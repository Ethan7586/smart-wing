## 3. 这个仓库的核心病理：必须先理解，否则会重复犯错

根 `.git` 曾长期断裂 → 无法 merge/diff/revert → **合并靠复制目录**（工作树中曾存在 16 份完整仓库副本）→ 手工复制会静默丢代码。

实测：当前工作树相对基线曾丢失 **28 个文件、31 个导出符号、约 1816 行**。典型如 `publicRoutes.ts` 从 495 行退化到 253 行，`auth-web` 整套注册函数消失。

**因此，铁律：**

> 看到任何"缺失、重复、架构不对"的现象，**第一反应是 `git show 77b0500:<文件>` 查基线**，不是动手写。

前一任因违反此律连续犯了三次错，都已更正，**不要重犯**：

| 错误结论                                            | 实际情况                                                                                                             |
| --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| "`routes/` 从未接线，43 个端点不可达，需要接通路由" | 基线 `router.ts` 是 **44 行薄组合器**，早已委派给 4 个子路由。清单的 P0C03 **已完成**。是工作树退化回了 295 行 if 链 |

## 6. 工作方式

### 6.1 修改清单逐条执行

依据 `docs/福利商城架构和补齐修改清单.md` 第 26 节（152 个修改点，P0A→P3）。

每完成一个修改点：

1. 跑 `node scripts/audit/index.mjs --summary`，确认无新增断裂与重复。
2. 跑受影响 workspace 的测试。
3. 与清单文档核对该点，不一致则修到一致。
4. 与 `docs/福利商城功能清单.xlsx` 核对（275 个功能项 + 20 个接口），不一致则修到一致。
5. 提交，commit message 说明依据的修改点 ID。

**不要为了"完成"而跳过验证。** 清单文档自评全量工作量为 244–410 人周，单次会话不可能完成全部 152 项；做完一批就如实报告进度与剩余项，不要伪装完成度。

### 6.2 编码约束

- DDD 分层：`domain`（零 IO）→ `application` → `interface`；`infrastructure` 实现 `port`。跨模块只经 port 或领域事件。
- SOLID、迪米特法则；一个文件一个主要公共概念，超约 300 行先按职责拆分。
- 命名：目录用单数小写英文；类/组件 PascalCase；函数/变量 camelCase；常量 UPPERCASE。**除 cli、代码审计、配置文件、SQL 迁移和测试外，自有文件与目录名不得出现下划线、连字符、空格或无意义缩写。**
- 金额一律整数分，禁止浮点。
- 禁止重复逻辑与重复配置；禁止调用点断裂。
- 彻底移除演示态与兼容层，不保留转发别名。
