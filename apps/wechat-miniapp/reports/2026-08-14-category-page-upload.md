## 本次 bug 与确认根因

1. 截图中的“本页将在阶段 2 建设”来自 Git 旧版占位页；当时的新分类代码没有完成提交和重新编译。
2. 旧服务层请求 `/api/v1/categories`，但 `commerce-api` 没有这个路由；这不是数据库为空。
3. 旧 `BASE_URL` 为空，所以页面不可能发出真实请求。
4. 旧分类数据只有“精选”，其余一级分类被明确置空，且所有图片为 `null`。
5. 左侧分类切换固定读取 `demo.categoryTiles`；即便首屏未来拿到接口数据，切换后仍会退回演示数据或空白。
6. 主 Shop 的真实商品接口是 `/api/v1/products`，它要求会员授权上下文。Web 使用 Host-only Cookie，小程序目前没有可用的 Bearer 令牌签发/校验通道，因此不能安全复用 Web 登录，也不能直连数据库。

## 修复内容

- 新建跨端分类契约 `packages/api-contract/src/catalog-taxonomy.json`；主 Shop Web 和小程序生成物从同一份数据读取，不再维护两套分类真值。
- 小程序现有六个左侧入口全部非空：精选、食品饮料、家用电器、数码办公、家居日用、个护清洁。
- 精选区严格按批准设计板提供 12 个子类目；完整契约包含 9 个一级类目和 31 个末级类目。
- 商品异步增强改走现有 `/api/v1/products`，不再请求不存在的分类接口。
- 分类页先同步载入稳定结构，再异步增强商品封面与数量；网络或登录失败不会把整个页面打成空白。
- 增加 `local / syncing / live / empty / auth / offline / timeout / error` 状态，支持重试、最新请求胜出、重新加载/卸载时中止在途请求。
- “当前会员可见”与“其中可购”分别计数，避免把可见商品误称为全部可购。
- 切换分类统一读取当前快照的 `tilesByKey`，彻底移除回退旧 demo 的路径。
- 无正式商品图时使用中性图片槽；这是 D3 正式影像素材尚待 Ethan 裁决，不是无数据或破图。
