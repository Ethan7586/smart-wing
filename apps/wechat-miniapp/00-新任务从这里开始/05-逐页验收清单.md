# 逐页验收清单

每完成一个阶段，必须在微信开发者工具真实渲染中检查，不能只看源代码或浏览器模拟图。

## 全局

- [ ] 用户界面只出现“会员码”，没有“翼码”命名漂移。
- [ ] 品牌名、Logo、主色、字体、图标来自正式资产与令牌。
- [ ] 没有 emoji 图标、假 Logo、破图、CSS 拼接二维码。
- [ ] 胶囊、刘海、状态栏、底部安全区没有遮挡。
- [ ] 五栏底部导航一致，中央会员码位置和尺寸正确。
- [ ] 页面无横向溢出、双滚动条和内嵌滚动冲突。
- [ ] 有骨架、空、失败、离线和重试状态。

## 首页

- [ ] 头部品牌与企业身份清晰，购物车可见且有克制角标。
- [ ] 搜索、余额、认证提醒、四入口、主视觉顺序与设计板一致。
- [ ] 主视觉没有廉价 emoji 礼盒或临时插画。
- [ ] 商城分区、会员码快捷入口和推荐商品完整。
- [ ] 普通卡片没有重阴影和过大圆角。

## 分类与商品

- [ ] 分类层级清晰，没有横向裁切。
- [ ] 商品图真实或使用正式本地占位图。
- [ ] 价格、福利资格、配送与来源信息可读。
- [ ] 添加购物车动作不是一整条夸张胶囊按钮。

## 会员码

- [ ] 二维码与条形码均有足够静区。
- [ ] 倒计时、刷新、调亮、截图警示和安全状态齐全。
- [ ] 会员卡使用智慧蓝渐变和正式翼纹。
- [ ] 会员码明确“不等于支付码”。
- [ ] 五种异常状态都有图标、文字和颜色，不只靠颜色。

## 购物车、结算和订单

- [ ] 购物车入口没有消失，数量状态一致。
- [ ] 多来源商品能解释拆单与履约方。
- [ ] 福利支付与个人支付分开说明。
- [ ] 未接真实支付时明确显示测试/待接入，不伪装成功。
- [ ] 支付结果、退款和售后以后端状态为准。

## 我的与安全

- [ ] 会员身份、手机认证、企业和资产来自当前用户，不写死 Ethan/张建国。
- [ ] 退出登录位置明确，反馈及时。
- [ ] 未认证、冻结、会话失效等状态有清晰下一步。

## 对比提交格式

每次验收需同时提供：

1. 对应批准设计稿的局部截图。
2. 微信开发者工具相同区域的真实截图。
3. 差异清单：一致 / 有意适配 / 尚未完成。
4. 下一步建议。
5. 本次 bug 的复现步骤、确认根因，以及“已证实事实 / 尚未证实猜测”的区分。
6. 修复文件、数据来源、实际返回数量，以及加载 / 成功 / 空 / 离线 / 超时 / 失败 / 重试状态。
7. 本地门禁结果、开发者工具 Console 结果、预览或上传版本号与时间。

涉及上传时，报告必须分别写明 `open`、`compile`、`preview`、`upload` 四步是否成功；缺少任何一步不得用“已上传”概括。证据图片必须复制到仓库报告目录，不能引用会消失的 Temp 路径。

不得只说“已完成”或“差不多”。
