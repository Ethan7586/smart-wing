## 2. VI 在哪，怎么查

### 2.1 一句话规则

> **数值查 JSON，解释查 MD，构图查 PNG。三者冲突时：数值以 JSON 为准，构图以 PNG 为准，冲突必须报告，不得自行取舍。**

### 2.2 我要一个颜色

**唯一来源**：`packages/design-system/src/tokens.json` → `color`

```
color.brand.primary        #1F5EFF   智慧蓝，主色
color.brand.primaryHover   #174ED1   交互深蓝
color.brand.dark           #143A8F   深海蓝
color.brand.ink            #07182F   夜空蓝
color.brand.light          #EAF1FF   浅品牌蓝

color.surface.background   #F5F7FA   页面底色
color.surface.base         #FFFFFF   卡片白
color.surface.subtle       #F8FAFC   次级面
color.surface.border       #E2E8F0   边框
color.surface.borderStrong #CBD5E1   强边框

color.text.primary         #172033   正文墨
color.text.secondary       #475569   次级文字
color.text.muted           #64748B   辅助文字
color.text.disabled        #94A3B8   失效
color.text.inverse         #FFFFFF   反色

color.semantic.success     #0F9F6E   成功
color.semantic.warning     #F59E0B   警示
color.semantic.danger      #DC2626   风险
（每个 semantic 还有 Strong 和 Surface 两档）
```

品牌渐变固定：`linear-gradient(135deg, #1F5EFF 0%, #143A8F 100%)`

**在小程序里怎么用**：不要抄上面的十六进制。用生成好的变量：

```css
color: var(--sw-text);
background: var(--sw-brand-light);
background: var(--sw-brand-gradient);
```

变量名规律：`tokens.json` 的路径去掉分组、转 kebab-case，加 `--sw-` 前缀。全表见 `miniprogram/styles/tokens.wxss`（自动生成，可以读，不可以改）。

**禁止**：新建近似蓝、AI 紫、餐饮金；大面积使用状态色；只靠颜色表达状态（必须同时有图标和文字）。

### 2.3 我要一个字号

**唯一来源**：`tokens.json` → `typography.styles`

单位是 **pt**。小程序是 **rpx**。换算固定 **1pt = 2rpx**（设计宽度 375pt = 750rpx）。

| 名称      | pt  | 行高 pt | 字重 | 小程序变量                  |
| --------- | --- | ------- | ---- | --------------------------- |
| display   | 32  | 40      | 700  | `--sw-fs-display` = 64rpx   |
| h1        | 28  | 36      | 700  | `--sw-fs-h1` = 56rpx        |
| h2        | 20  | 28      | 600  | `--sw-fs-h2` = 40rpx        |
| h3        | 17  | 24      | 600  | `--sw-fs-h3` = 34rpx        |
| body      | 16  | 24      | 400  | `--sw-fs-body` = 32rpx      |
| bodySmall | 14  | 20      | 400  | `--sw-fs-bodySmall` = 28rpx |
| caption   | 12  | 18      | 400  | `--sw-fs-caption` = 24rpx   |
| amount    | 28  | 34      | 700  | `--sw-fs-amount` = 56rpx    |

每个都有配套的 `--sw-lh-*`（行高）和 `--sw-fw-*`（字重），成套用，别只用字号。

字体族：中文 `--sw-font-cn`，金额与数字 `--sw-font-num`。
**金额必须用 `--sw-font-num` 并加 `font-variant-numeric: tabular-nums`**，否则一列价格对不齐。

底栏标签是小程序平台专属尺寸：`mobile-platforms.json` 中 `tabLabelSize: 20`、`tabLabelLineHeight: 28`，生成后使用 `--sw-tab-label-size / --sw-tab-label-line-height`。

### 2.4 我要间距和圆角

**间距**：`tokens.json` → `spacing`，pt 值，同样 ×2 得 rpx。

```
--sw-space-half   8rpx      --sw-space-3   48rpx
--sw-space-1     16rpx      --sw-space-4   64rpx
--sw-space-1_5   24rpx      --sw-space-5   80rpx
--sw-space-2     32rpx      --sw-space-6   96rpx
                            --sw-space-8  128rpx
```

**页面左右边距固定 32rpx** → 用 `class="sw-inset"`，不要自己写 padding。

**圆角**：`tokens.json` → `radius`

```
--sw-radius-small       16rpx   小组件
--sw-radius-medium      24rpx   控件
--sw-radius-large       32rpx   卡片
--sw-radius-extraLarge  48rpx   会员卡、大弹层
--sw-radius-full      9999rpx   胶囊
```

**禁止**自创 28rpx、30rpx 这类自由值。

**阴影**：普通卡片用**浅边框**，不用阴影。阴影只允许四处：浮层、底栏、中央会员码、数字会员卡。变量 `--sw-shadow-card / --sw-shadow-overlay / --sw-shadow-membercode`。

**触控**：`--sw-touch-min` = 88rpx。小控件不得小于它。

### 2.5 我要一个图标

**优先级固定**（`03-设计原稿与资产索引.md` 定的，不许跳级）：

```
1. 项目正式品牌 SVG        packages/design-system/src/brand/
2. 已批准设计图对应图标
3. React 原稿用的 Lucide   node_modules/lucide-react   ← 绝大多数走这里
4. Android 原稿的 Material Symbols

**同一页面不得混用多个图标家族。** 目前全项目只用 lucide + 品牌 SVG，别引第三套。

lucide 为什么合规：它是 24×24 网格、stroke-width 2、圆角端点 —— 和 `tokens.json` 的 `icon.strokeWidth: 2` / `icon.sizes.standard: 24` 完全一致。许可证 ISC，商用免费，界面无需署名。共 1868 个图标。

**加一个图标的完整流程**（见第 4.3 节，只有四步）。

**缺图标时必须停下来登记，不得临时补画。** 这是硬规则。

## 4. 架构：VI 怎么变成小程序代码

### 4.1 为什么必须有管道

微信小程序有三个硬限制：

1. **WXSS 不能 `@import` miniprogramRoot 之外的文件** → 拿不到 `packages/design-system/src/tokens.css`
2. **`<image>` 不可靠地渲染 SVG** → 品牌 SVG 不能直接当图片用
3. **`lucide-react` 是 React 组件** → 小程序里跑不了

结果：小程序目录里**天然没有任何可用资产**。这时候要放一个购物车图标，最省力的写法就是 `border: 2rpx solid` 画个方框。

**前两次就是这么丑的。不是审美问题，是物料缺口 + 省力路径指向了错误方向。**

管道的作用只有一个：**让正确的做法变成最省力的做法。**

### 4.2 管道长什么样

```
真值（只读，不许在管道里改）
  packages/design-system/src/tokens.json            颜色 字号 间距 圆角 图标规格
  packages/design-system/src/mobile-platforms.json  小程序专属尺寸
  packages/design-system/src/brand/*.svg            4 个品牌图形
  node_modules/lucide-react                         1868 个图标几何
                    │
                    ▼
        scripts/build-miniapp-assets.mjs
                    │
                    ▼
生成物（只许生成，不许手改）
  miniprogram/styles/tokens.wxss    所有 CSS 变量 + 品牌图形 base64
  miniprogram/styles/icons.wxss     .i-<名字>-<颜色> 图标类，base64 背景图
```

两个关键设计：

**① 变量声明在 `page, .sw-tokens` 两个选择器上。**
`custom-tab-bar` 渲染在 page 节点树之外，只声明 `page` 它拿不到 —— 这就是上一版底栏颜色、阴影、上浮全部失效的原因。任何 page 之外的根节点加 `class="sw-tokens"` 即可继承。

**② 图标用 base64 背景图，不用 `<image>`。**
因为 `<image>` 不可靠渲染 SVG，而 WXSS 的 `background-image: url("data:image/svg+xml;base64,...")` 稳定可用。代价是颜色烧死在图里，所以每个图标按需生成多个颜色变体。

**③ 只生成用得到的。**
生成器里有 `MANIFEST`，列出每个图标要哪些颜色。没在清单里的图标不会生成 —— 强制"缺图标就登记"，而不是悄悄多塞一堆备用。

### 4.3 加一个图标：四步

```
1. 去 https://lucide.dev 找图标，记下 kebab-case 名字（如 shopping-cart）
2. 打开 scripts/build-miniapp-assets.mjs，在 MANIFEST 加一行：
     'shopping-cart': ['ink'],
   颜色可选：ink secondary muted brand white danger success
3. npm run build:miniapp-assets
4. WXML 里用：<view class="i i-shopping-cart-ink"></view>
```

尺寸：默认 48rpx（标准）。要别的加一个类：`i-sm`(32) `i-md`(40) `i-lg`(56) `i-xl`(64)。

数据驱动的图标（`i-{{item.icon}}-brand`）也要在 MANIFEST 里，检查器会验数据文件里的图标名。

### 4.4 加一个页面：五步

```
1. mkdir miniprogram/pages/<名字>
2. 建四个文件：<名字>.js / .json / .wxml / .wxss
3. .json 里写 { "navigationStyle": "custom", "backgroundColor": "#F5F7FA", "usingComponents": {} }
4. app.json 的 pages 数组加路径（tabBar 页还要加到 tabBar.list）
5. .js 的 onShow 里设置底栏选中态：
     if (typeof this.getTabBar === 'function' && this.getTabBar()) {
       this.getTabBar().setData({ selected: <序号> });
     }
```

顶部安全区：`app.getSafeArea()` 拿 `statusBarHeight / navContentHeight / navTotalHeight / rightInset / safeAreaBottom`，**全部是设备实测值，永远不要写死**。

## 5. 防线：`npm run check:miniapp`

`scripts/check-miniapp-vi.mjs`。**每条规则都对应 `06-事故记录` 里的一次真实翻车。**

| 规则                  | 拦什么                           | 对应事故                |
| --------------------- | -------------------------------- | ----------------------- |
| `cover-view`          | 用了 cover-view                  | #8 样式被原生层静默丢弃 |
| `hardcoded-color`     | WXSS/JS 里写了十六进制           | #3 没用令牌             |
| `untokenized-color`   | JSON 配置里的色值不在调色板内    | #3                      |
| `css-drawn-icon`      | `border-radius: 50%`             | #4 CSS 画图标           |
| `pseudo-element-art`  | `::before` / `::after`           | #4                      |
| `emoji`               | emoji 或字符图标                 | 02 VI                   |
| `name-drift`          | 出现「翼码」                     | #6 命名漂移             |
| `hardcoded-safe-area` | 写死顶部距离                     | #6 安全区写死           |
| `flex-gap`            | 用了 flex `gap`                  | 低版本安卓不稳          |
| `stale-generated`     | 生成物与仓库不一致               | 新增                    |
| `generated-edited`    | 手改了生成文件                   | 新增                    |
| `missing-icon`        | 用了没生成的图标（含数据驱动的） | #4 会渲染成空白         |

**豁免机制**：同一行写注释 `vi-allow: <规则名> — <理由>`。**不写理由本身也算失败** —— 让"悄悄绕过"不比"好好做"更省力。

已有两处合法豁免：中央会员码的白色圆形容器、轮播指示点。都是几何容器，不是图标。

## 6. 微信平台的五个坑

写之前先记住，这五个每一个都能让页面看起来"莫名其妙就是不对"。

**① `cover-view` 会静默丢样式**
它由原生层渲染，不支持 `::before`、`linear-gradient`、`box-shadow`，也拿不到 CSS 变量。**只在需要盖住 map / video / canvas / camera 时才用**，其余一律 `view`。上一版底栏代码其实写对了，就因为用了 cover-view，全部样式被丢掉，渲染成黑方块。

**② `page` 上的 CSS 变量到不了 custom-tab-bar**
它在 page 节点树之外。解决：变量同时声明在 `.sw-tokens`，组件根节点加这个类，组件 `.json` 设 `"styleIsolation": "shared"`。

**③ `<image>` 不可靠渲染 SVG**
用 WXSS `background-image` + base64。已由管道统一处理。

**④ flex `gap` 在旧版安卓基础库不稳**
一律用 `margin`。检查器会拦。

**⑤ 顶部距离必须实测**
`wx.getWindowInfo()` + `wx.getMenuButtonBoundingClientRect()`。写死会在刘海屏和灵动岛上撞车。已封装在 `utils/safeArea.js`。

**排错顺序**（`06-事故记录` 第 8 条）：

```
先读本地 WXSS/WXML/JS 编译错误
→ 再看 Console
→ 再看 Network
→ 最后才怀疑代理 / VPN / 网络
```

**白屏绝大多数是本地语法错误，不是网络。** 不许一上来就归因于 v2rayN。

以下是小程序真实闭环需要的接口清单。2026-08-14 以前它们均未实现；现在订单、登录、会员码和账号安全相关接口已经获准建设，但在代码、数据库迁移、自动化测试、开发者工具和真实环境均通过前，不得把“施工中”写成“完成”：

GET  /api/v1/orders/by-no/{orderNo}       微信订单中心进入的本人订单详情
```

**原有结构性障碍仍必须彻底解决**：Web 端用 `__Host-` Cookie 会话，**小程序没有 cookie 容器**。本轮允许实现短期 Bearer 令牌通道（绑定 member / membership / session / device / authzVersion）。小程序是会话传输渠道，会员权限目标仍是 `storefront`；不得为了小程序另造一套平行权限模型。

订单中心登记的是**订单详情路径**，不是商品详情路径。实现使用 `pages/order-detail/order-detail?orderNo=${商品订单号}&channel=wechat_order_center`（后台登记时不加开头 `/`）；`${商品订单号}` 由微信按 JSAPI 下单的 `out_trade_no` 替换。页面收到订单号后只能把它当查询键，服务端仍须按当前登录会员重新校验订单归属。
